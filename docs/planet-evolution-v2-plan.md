# 星球演進 v2：分階段規劃

## 已拍板（2026-10-16）

| 決策 | 選擇 | 影響 |
|---|---|---|
| v1 怎麼處理 | **直接在 v1 上改** | 不開新專案；v1 的 135 個測試全部當回歸測試。換表示法（P2）要在同一套程式碼裡並存比較 |
| 觀看方式 | **即時看著演化** | 每步有效能預算：n=150 至少維持 v1 的約 10 步／秒。比較貴的物理要分攤到多步或降頻 |
| 跑多久 | **陸地集中成兩大塊（可以有澳洲、格陵蘭那種大島）就停** | 停止條件是**陸地的形狀**，不是年數。定義見「停止條件」一節 |
| 落地到 2,000 萬格 | **每格記錄狀態資訊，先不做細節**；未來當作建立 3D 場景的參考 | P1 變成資料表設計＋屬性轉移，不做碎形；見 P1 |

---

## 為什麼要重做

v1（`Planet.Simulation`，2026-09-05 ~ 09-10）做出了會長大陸、會隱沒、會開海盆的星球，
但有幾個問題是**結構性的**，只修症狀會越修越複雜：

| 問題 | 根源 | v1 的處理 |
|---|---|---|
| 海岸線碎裂、滿地一格島 | marker-in-cell 一格一個標記，每兩步重新取樣，**每步約 1,200 格在海陸間翻面** | 匯出前清除（治標） |
| 板塊作用批次化 | 標記要累積跨過一格才動，n=24 每 20 步一次 | 無 |
| 同種子跨行程結果不同 | 至少一個來源未找到（差 18% 步數） | 部分修正 |
| 參數彼此牽動 | 水量重校了 6 次、模型一改就作廢 | 每次重新夾逼 |
| 從沒交付過 | 落地到 2,000 萬格排在最後，五天沒走到 | — |
| 只有一個全球海平面 | 注水不看連通性 | 鑿通內海 |
| 氣候每 200 萬年跳一次 | 階梯狀的溫度造成冰與海平面震盪 | 無 |

「重做」的意思是**重新安排順序、補上缺的地基、換掉有問題的表示法**，不是丟掉 v1。
v1 量到的物理（岩石圈浮力在 18 Myr 翻轉、洋脊深 −2,500 m、熱沉降 350√t…）與
驗證過的機制（線段式板塊作用、海洋出口鑿通、海浪按暴露邊數計費）都直接沿用。

---

## 五條原則

1. **先打通，再做好。** P1 結束時就要能在走動模式裡踩在模擬出來的地形上，哪怕那顆星球很醜
2. **重現性與存檔是地基。** 同種子在任何機器、任何行程都給出位元相同的結果，有跨行程測試盯著
3. **每個機制上線時就帶著觸發計數與質量收支。** v1 至少三次「機制從沒觸發」、兩次「回報成功但沒生效」，事後統計都看不出來
4. **驗收是一組固定的儀表，不是看一個數字。** 見最後「固定儀表」
5. **即時觀看有效能預算。** 每個新機制都要量每步耗時；超過預算就降頻或分攤，不能悄悄拖慢

## 停止條件：「陸地集中成兩大塊」

**比照地球**：亞非歐大陸約佔陸地 57%、美洲約 28%、澳洲 5.2%、格陵蘭 1.5%。

| 條件 | 預設門檻 | 地球 |
|---|---|---|
| 最大的兩塊陸地合計佔陸地 | ≥ 75% | 85% |
| 兩塊**各自**佔陸地 | ≥ 20% | 57% / 28% |
| 大島（佔陸地 1%~10%）的數量 | **≥ 2 塊**（使用者指定） | 澳洲、格陵蘭、南極…約 4 塊 |
| 兩塊**各自**的海岸破碎度（2026-10-17 加入） | **≤ 4** | 估計 2~3 |
| 陸地（排除碎島）佔星球表面（2026-10-17 使用者定） | **≥ 20%** | 29% |
| 海洋面積 | 60%~72%（**監看，不當停止條件**） | 71% |

- 「一塊陸地」＝陸地格的連通塊（`OceanTopology` 已經算得出來，每次約 33 ms）
- 判斷前先排除碎島（小於 1,000 km²），否則上千個一格島會把比例攤薄
- **每 20 萬年檢查一次，條件成立就自動暫停**，畫面上提示、並自動存檔。使用者可以看一看再決定要不要繼續
- 門檻做成可調參數，第一次看到結果之後很可能要調
- **陸地至少 20%** 是 P4 時補的：比例條件只看陸地「內部」的分配，陸地只有 1~2% 時一兩個小島也會符合
  「兩大塊＋大島」，停止條件在幾乎沒有陸地的星球上就成立了
- **海岸破碎度**＝海岸格數 ÷ 同面積圓盤的海岸格數（1 ＝ 圓盤）。內部湖洞也算海岸，所以不另外量湖。
  加入的原因見下面「v1 第一次觸發時的實況」

**v1 第一次觸發時的實況**（2026-10-17，n=150、種子 42、第 1,160 步）：比例是 50.8% ＋ 30.3%、大島 4 個，
全部過門檻，但畫出來**不是兩片完整的陸地**——每塊都是沿板塊邊界彎成弧形的細長山脈帶、串起半淹的碎塊，
像一張網。使用者要的是「兩大塊，但每塊要完整」，所以加了破碎度。量到的數字：

| 量 | 第 1 大 | 第 2 大 |
|---|---|---|
| 海岸破碎度 | **12.6** | **12.5** |
| 只碰到這塊大陸的湖洞 | 349 個（656 格） | 276 個（429 格） |
| 周圍 3 格內的小碎片 | 167 塊 | 158 塊 |
| 把湖洞全部填掉後的破碎度 | 9.2 | 9.3 |

全球 770 塊陸地（482 塊只有一格）。碎的來源有兩個：
1. **大陸內部夾著海洋地殼（胡椒狀）**：被大陸地殼包圍的洋殼格有 2,622 格，93% 在板塊內部、
   年齡中位 30 Myr（不是新生的）、厚度中位 19 公里（遠比正常洋殼厚）。陸地上一共有 10,857 格是洋殼，
   其中 8,222 格在海岸。填洞只能修掉約四分之一的破碎度。
2. **大陸的形狀本身是弧形**：陸地是沿聚合邊界長出來的造山帶，繞著大洋板塊排成環。這是 P3／P4 的問題，
   事後修飾修不了。

加了破碎度之後，**v1 在第 1,160 步不再算成立**；可能整個旋迴都不會成立。這是預期中的：
要等 P3／P4 把大陸的生成與聚集修好。

**v1 的對照數據**（水量 1,150、第 1,600 步）：最大幾塊佔陸地 66.9% / 18.2% / 3.4% / 3.4%——
一塊超大陸、一塊中型大陸、兩個澳洲大小的島。合計 85% 與大島 2 塊都已過門檻，**只差第二塊 18.2% 還沒到 20%**。
所以 v1 的模型是有機會走到這個狀態的，只是沒有人在對的時間停下來。

**風險**：板塊構造是循環的（威爾遜旋迴），兩大塊可能只是一個短暫的過渡狀態。
自動暫停就是為了這個——錯過了不會再等一個旋迴。

## 階段總覽

```
P0 地基 ──→ P1 端到端管線 ──→ P2 表示法選型 ──→ P3 板塊運動學
                   │                                    │
                   └──── 每一階段都能在走動模式裡看到 ───┤
                                                        ↓
                        P4 地殼生成與消滅 ──→ P5 水與海洋 ──→ P6 氣候與冰
                                                                  ↓
                                         P7 外營力 ──→ P8 校準 ──→ P9 交付
```

| 階段 | 內容 | 預估 |
|---|---|---|
| P0 | 地基：重現性、完整存檔、停止條件、儀表 | 2~3 天 |
| P1 | 端到端：粗網格狀態 → 2,000 萬格的每格資訊 → 走動模式 | 3~5 天 |
| P2 | 岩石圈表示法：在 v1 裡並存三種、用數字選 | 3~4 天 |
| P3 | 板塊運動學：整理 v1 的板塊與邊界 | 1~2 天 |
| P4 | 地殼生成與消滅 | 3~5 天 |
| P5 | 水：依盆地注水、湖泊、海洋連通 | 3~4 天 |
| P6 | 氣候與冰：連續的溫度、海洋熱輸送 | 3~4 天 |

| P8 | 校準 | 2~3 天 |

## P0 地基

**目標**：之後每一階段都不必再為「這個結果能不能信」煩惱。

- **決定性**：所有平行加總用固定切片數；每個子系統各自的亂數產生器，由主種子衍生；
  平行迴圈不准「寫自己、讀鄰居」
- **找出 v1 剩下的那個跨行程分歧**（離線約 2,350 步、線上 1,975 步）。做法是兩個行程逐步比對狀態雜湊，找出第一個分歧的步數與欄位
- **跨行程重現測試**：兩個獨立行程跑同一種子，比對狀態雜湊。v1 一直缺這道
- **完整存檔**：v1 已寫好的 `SimulationSnapshot`（未提交）**要加上標記**，讀回續跑才會位元相同。
  即時觀看時服務一重啟就要能接回去，這件事比 v1 時更重要
- **停止條件**：實作上一節的判斷、自動暫停、自動存檔，前端顯示「為什麼停了」
- **儀表端點**：一次回傳「固定儀表」的全部數字
- **效能基準**：每步耗時分項計時（板塊、火山、侵蝕、氣候、注水…），之後每個階段都對照

**驗收**：兩行程同種子 2,000 步狀態雜湊相同；存檔→讀回→再跑 500 步，與不中斷的結果相同；
用 v1 跑一次，停止條件會在某一步觸發（或明確量到它一直沒觸發）。

### P0 結果（2026-10-17 完成）

- **「v1 的跨行程分歧」不是非決定性，是兩邊跑的不是同一顆星球。** 測試各自用寫死的半徑，
  跟服務從 `GoldbergPlanetGenerator` 推出來的差了 **4.3 毫米**；混沌系統把它放大成
  幾千步之後的分岔。現在測試一律用 `TestPlanet.RadiusMeters`。
  決定性本身用 `DOTNET_PROCESSOR_COUNT=1` 與 `=8` 各跑一次比對確認過：核心數不影響結果。
- **存檔續跑位元相同**（格式 v3）。v1 的存檔漏了三樣東西，補一樣還是分岔、補兩樣還是分岔：
  標記與 cell bucket、板塊重新分配的累積量（`_seedDriftMeters`、`_driftAngleSinceFullScan`、
  `_assignMargin`）、熱柱亂數的抽取次數。最後一個漏存（`_seedDriftMeters`）是用**反射掃描所有私有欄位、
  逐欄比對存檔前後的雜湊**找到的——比讀程式碼猜快得多，之後加狀態欄位時可以照做
  （`StateHash.PerField`）。守門測試：`RoundTrip_ResumeIsBitIdenticalToUninterruptedRun`
  （第 317 步存檔、續跑 300 步、每步逐欄比對）。
- **停止條件會觸發**：v1、n=150、種子 42、200 Myr，第一次成立在**第 1,160 步（58 Myr）**：
  50.8% ＋ 30.3%、大島 4 個。之後在 61、64、69、173~178 Myr 都再成立過，中間會散掉
  （110~150 Myr 幾乎是一塊超大陸，最大一塊 84~98%、大島 0 個）——符合「配置會出現、維持一陣子、
  然後散掉」的預期，所以自動存檔是必要的。
  **但觸發當下海洋是 79%**，高於監看範圍 60~72%；整段期間海洋從 95% 單調降到 49%。
  水量與海洋比例要在 P5／P8 處理，目前只監看。
- **儀表端點**：`GET /api/simulation/dashboard`（`?resetTimings=true` 重設計時）。
  分析都在 `Planet.Simulation.SimulationDiagnostics`，服務只負責組裝。

## P1 端到端管線（先通再好）

**目標**：在走動模式裡踩在模擬出來的地形上。

### 每格記錄什麼

決策是「每格記錄狀態資訊，先不做細節，未來當 3D 場景的參考」。2,002 萬格 × 每格十幾個浮點數
大約 1 GB，直接全部塞進 `Tiles` 太重，而且 89 個細格本來就共用同一個粗格的資料。建議分兩層：

| 放哪裡 | 內容 | 大小 |
|---|---|---|
| `Tiles`（既有，2,002 萬列） | **新增 `SourceCellId`**；改寫走動模式直接要用的欄位：地形類型、高度等級、海平面等級 | 每列 +4 bytes，約 80 MB |
| **新表 `PlanetCells`**（22.5 萬列） | 粗格的完整狀態：地殼類型／厚度／年齡／密度、板塊、邊界類型、溫度、降水、水深、冰厚、沉積、火山活動… | 約 20 MB |
| `PlanetMetadata` | 來源：種子、存檔名稱、步數、年代、程式版本 | 一列 |

這樣每一格都查得到完整的地質狀態（經由 `SourceCellId` 接到 `PlanetCells`），而且之後要加欄位
只改 22.5 萬列的表，不必重寫 2,000 萬列。

### 高度內插（2026-10-17 拍板：做）

「先不做細節」照字面是**最近的粗格**：89 個細格拿到完全相同的高度，地面會是一塊塊約 9 公里寬的平台，
平台之間是高度落差。走動模式的地形規則（上坡限 2 級）會讓很多平台邊緣變成走不過去的牆。

折衷是**只有高度用三個最近粗格做重心內插**（其餘屬性仍取最近粗格）。這不是加細節，只是把階梯抹平，
成本很低。**2026-10-17 使用者同意做。**

### 寫入

- 沿用 `/api/admin/regenerate` 的長時間工作＋進度回報模式
- **會覆蓋 2,000 萬列**：先寫進新表再一次切換，或先備份，不可以邊寫邊覆蓋
- 碎島清除在放大**之前**做（粗網格上便宜得多）

**驗收**：從存檔一鍵產生 → 走動模式可以走 → 地形與總覽貼圖一致 → 任選一格查得到完整的地質狀態。

### P1 結果（2026-10-17，在試寫用的 `PlanetDbP1` 上驗收）

- **一鍵產生**：`POST /api/admin/materialize?snapshot=名稱`（要 `X-Admin-Key`），`GET` 同一路徑看進度。
  第 1,160 步的存檔放大成 20,022,252 格花了 **527 秒**（同時跑測試時 858 秒），碎島清除沉了 484 個粗格。
  寫入期間舊地圖照常可以查（實測 `nearby` 1.7 秒內回應）；切換後主鍵與索引名稱正確、沒有殘留的暫存表。
- **走動模式可以走**：從海上跑上岸，海拔一路 −150 → −45 → 0 → 5 公尺，海岸沒有牆。
- **總覽貼圖一致**：總覽改從 `PlanetCells` 取樣（`PlanetMetadata.SimulationFrequency` 不是 null 就走這條），
  跟模擬的地形圖是同一個地理。
- **任選一格查得到地質狀態**：`GET /api/tiles/{id}/geology`。
- **踩到的坑：模擬的降水是相對尺度，不是公釐／年**（`SimulationState` 的說明寫錯了，`Climate` 的註解才是對的）。
  第一次試寫用地球的公釐門檻分植被，陸地**全部**變成沙漠、一格草或林都沒有。改成依陸地降水的**排名**分
  （最乾 20% 沙漠、15% 灌木、30% 草原、其餘林地），並加了守門測試。
- **要注意的量**：海拔等級最高 **2,603 級（約 13 公里）**、最低 −699 級。程序化地形是 ±500 級；
  畫面有 ×8 起伏誇張，高原與山脈在走動模式裡會是很高的牆。這是模擬本身的高度（陸地 75 百分位 2,890 公尺），
  屬於 P8 校準，P1 不處理。

**部署到正式環境的順序**：新程式會查 `Tiles.SourceCellId`，所以**一定要先**對 `PlanetDb` 套用遷移
`AddPlanetCellsAndSimulationSource`，**再** publish；反過來的話正式站所有地塊查詢都會失敗。
套遷移只加可為 null 的欄位與一張空表，不會動到既有的 2,000 萬列。

## P2 岩石圈表示法（在 v1 裡並存比較）

**目標**：選一個**不會產生取樣雜訊**的方式表示「地殼跟著板塊移動」。

因為是直接在 v1 上改，三個候選做成**可切換的實作**，跑同一組比較，選定之後再拿掉其他兩個：

| 候選 | 做法 | 預期優點 | 預期風險 |
|---|---|---|---|
| A. 多標記＋體積守恆 | 每格多個標記，標記帶**體積**而不是厚度 | 改動最小 | v1 試過多標記會抹薄大陸（那時厚度由標記數推導；換成體積應該能避開——要驗證） |
| B. 板塊座標系 | 每個板塊在自己的旋轉座標系裡存地殼，只有邊界需要重新取樣 | 板塊內部**零雜訊**，最便宜 | 邊界合併與板塊分裂較複雜 |
| C. 半拉格朗日平流 | 場存在格子上，每步沿速度倒推取樣 | 實作簡單 | 數值擴散會抹開邊界 |

**評比**（純剛體旋轉 500 步，不做地質作用）：每步海陸翻面格數（v1 約 1,200，目標 < 50）、
質量守恆（< 0.1%）、邊界擴散、有沒有週期性批次化、**每步耗時**（即時觀看的預算）。

**驗收**：選定一個，理由與數字寫進文件。**這是整個 v2 最重要的決定。**

### P2 結果（2026-10-17）：選 **B 板塊座標系**

2. **邊界的轉交規則是必要的**：所屬板塊在某點沒有地殼時，先從舊歸屬與相鄰板塊轉交過來，都沒有才是張裂。

連帶也關掉了這條拼接的路。

#### 過程中排除的問題（每一條都是實測才看得到）

1. **Voronoi 平分線不是海溝**：歸屬跟著 Voronoi 時，平分線以兩側的平均速度移動，海溝在上盤上滑動、島弧被抹成
   一大片薄薄的增厚帶（陸地 7.8% 幾乎都是這種，大陸地殼一格都沒長）→ 改成歸屬跟著地殼。
2. **混合做法不可行**：「地殼決定歸屬、Voronoi 決定拖曳與空缺」兩個範圍一跑就差一半，力跟阻力算在不同範圍、
   Voronoi 裡的舊地殼在板塊內部冒出來重疊 → 滿地漩渦狀的條紋與碎陸地 → 改成設計 C。
3. **`VelocityAt` 用 Voronoi 板塊的速度**：邊界兩側常同屬一個 Voronoi 板塊，相對速度算成 0，邊界分類全亂
   （轉形 10,175、聚合 107），沒有板片拉力、所有板塊停到 0.01~0.16°/Myr。p4g 那張「乾淨」的地圖其實是板塊停住造成的。
4. **條紋的四個來源**：碎片被抄進隔壁板塊（厚地殼條紋）、補洞長新地殼（年輕地殼條紋，5,303 格靠轉形邊界）、
   裂縫火山的噴發口固定在網格上、空缺的新地殼給錯板塊。
5. **逐格的邊界規則會一直累積碎片**：試過約十種，歸屬一直碎成約 200 塊、邊界佔 10% 以上 →
   **以連通塊為單位的歸屬平滑**才收斂（210 塊 → 16 塊、邊界 10% → 4.5%、非邊界新生 460 → 12／步）。
6. **小板塊失控**：地殼快被吃光的板塊拖曳趨近 0，被轉到 18.8°/Myr → 速度上限。速度上限一度無條件套用，
   改變了 v1 的演化（`SmallIslandCleanupTests` 最大陸塊 484 → 486）→ 只在板塊座標系啟用。
7. **碎斑（海平面附近的增厚洋殼）**：縮短增厚的條件太寬，洋殼大片增厚浮到海平面
   （「浮力差 < 500 m」：10~20 km 增厚洋殼 3.7 萬格、海床中位深度 2,060 m；「淨浮力都 ≥ 0」：縮短 790 次／步、
   隱沒只剩 130）；增厚時密度往大陸拉，14 km 的洋殼密度掉到 2,800 浮起來 → 縮短只限大陸碰大陸、密度按質量混合
   → 胡椒 1,644 → 66、破碎度 1.6／1.4（50 Myr）。
8. **增生比例**：v1 的 3% 是因為標記法把增生放大約 35 倍才調低的；板塊座標系照搬 3% 大陸幾乎不長
   （50 Myr 大陸地殼 1.0%）→ 改回 10%（50 Myr 2.9%）。
9. 速度尺度不用另外校準：倍率 1 與 0.5 長期都收斂到約 6~7 cm/yr，速度由「板塊越快、隱沒的海床越年輕、
   拉力越弱」的回饋決定。

## P5 水與海洋

依連通性注水（與大洋相通的才是海；封閉盆地依降水與蒸發決定是湖、鹹湖或乾盆地），
沿用 v1 的海洋出口鑿通。**驗收**：主洋佔水域 > 95%；湖泊存在且不會被打通；水量守恆。

### P5 結果（2026-10-18／19，分支 `feat/p5-water`，**驗收通過**）

只在板塊座標系模式生效（`SimulationEngine.Hydrology`；標記法是 null，照舊用單一全球海平面，v1 行為不變）。

**做法**（`Hydrology`）：
1. **泛洪**：從上一步的主洋（地表低於上一步海平面的最大連通塊）做一次 priority-flood，
   每一格得到「通往主洋最低要翻過多高」。海平面是 L 時，這個高度 &lt; L 的格子才是海。
2. **盆地**：泛洪高度 &gt; 地表的連通塊，溢出口就是那個泛洪高度。小於 1,000 km² 或**淺於 150 m** 的不存水
   （當成已被河流切穿或被沉積填平），水繼續往下游流。
3. **集水與水量收支**：泛洪記下的流向就是灌滿之後的流向，每一格的逕流流進下游第一個盆地。盆地由低到高一格一格淹，
   淹進來的那一格從「逕流 P×r」變成「湖面 P − E」，淹到入水被蒸發抵銷為止 → 淡水湖（灌滿、溢出）／鹹湖／乾盆地。
   湖面蒸發 ＝ 全球平均降水 × 0.8 × 溫度因子（使用者在 1.0／0.6／0.4 之間比較後選 0.8）。
   逕流係數含**高山融雪**：降雪的比例依年均溫（−5°C 以下全是雪、5°C 以上全是雨），雪的部分逕流係數 0.8、雨 0.35。
4. **海平面**：總水量 − 冰 − 湖水 ＝ 海水。泛洪的處理順序就是泛洪高度由低到高，海水體積對海平面分段線性，
   用前綴和直接解（不用二分搜尋）。湖與海平面交替解到盆地不再變。
5. **河流**：沿流向把逕流往下游累加成每格流量（`Hydrology.Discharge`），湖溢出來的水從溢出口接著流。
   只是診斷與顯示，河谷侵蝕留到 P7。
6. **鑿通**：沿用 `SeaOutletBreach`，它只看「地表低於海平面」的封閉盆地，高於海平面的湖不會被打通。

**結果**（n=150、種子 42 劇本，40 Myr）：主洋佔水域 98.8%（全程 ≥ 98.7%）；淡水湖 6、鹹湖 6、乾盆地 4，
最大的是 A 北西部的淡水湖（約 13 萬 km²）；C 有完整的水系流進 B、C 之間的海灣；水量誤差 10⁻⁸ 等級。
注水每步約 50 ms（原本照 v1 每步 136 ms）。

**過程中修掉的坑**：
1. 完全不下雨時湖面蒸發也是 0，用「淨損失 ≤ 剩餘入水」判斷的話每一格 0 ≤ 0，盆地被憑空灌滿（起始到第一次解氣候之前就是這樣）
   → 要嚴格有剩才淹得進去。
2. 注水太慢：海平面每次照 v1 掃全球 60 輪二分（→ 前綴和）、盆地結構每輪重建（→ 每次泛洪建一次）、
   15 萬格主洋全部進優先佇列（→ 主洋內部直接排序，只有靠岸的進佇列；排序用基數排序）。
3. 鹹湖太多（蒸發 0.8 時 40 Myr 有 31 個）：起始地殼厚度的小起伏留下大量淺窪地，每個都成了集水區很小的封閉盆地
   → 淺於 150 m 的不存水，鹹湖降到 6 個，河流也才匯得起來。

**留給 P6 的問題：陸地又冷又乾。** 40 Myr 時陸地平均降水只有全球平均的 9%（海上 139%），中緯度陸地氣溫 −28～−48°C、
A 南幾乎沒有河。海平面在 40 Myr 內從 −200 m 掉到 −1,277 m（舊注水也一樣），大陸相對海平面高了約 1,100 m、冷了約 7°C，
推測是冰蓋鎖水的正回饋（冷 → 長冰 → 海平面降 → 大陸更高更冷）。河與湖的多寡要等 P6 把氣候修好再看。

## P6 氣候與冰

仍然解穩態，但兩次求解之間內插溫度場；加上海洋熱輸送；冰蓋供給上限。
**驗收**：海平面沒有週期性暴漲暴跌；冰帽面積與地球同量級。

### P6 結果（2026-10-19，分支 `feat/p6-climate`，**驗收通過**）

全部只在板塊座標系模式生效（標記法的溫度、冰、破碎度、地形都不變）。

**診斷**（種子 42 劇本，P5 結束時）：陸地又冷又乾。40 Myr 時冰蓋佔陸地 57%、鎖住 10.6% 的水，陸地平均高出海面 3.7 km、
45° 陸溫 −30°C，海平面每 200 萬年（解氣候的那一步）跳一截（−26 m，平常每步 0.8 m）。逐項量下來有三個來源：
冰只看氣溫、溫度兩次求解之間不動、**陸地本身越長越高**（海床變老只深了約 100 m；真正的原因是碰撞讓大陸變小變厚）。

**氣候與冰**：
1. **冰蓋要看降雪**（`Cryosphere.SnowLimited`）：平衡冰厚依「降雪 ÷（全球平均降水 × 0.25）」打折——乾冷的沙漠不長厚冰
   （冰期的西伯利亞夠冷但太乾，沒有大冰蓋）。冰鎖住的水 10.6% → 0.4%。
2. **溫度每步更新**（`Climate.UpdateTemperatureOnly`），降水照舊每 200 萬年解一次——溫度本身就連續，不用內插。海平面的週期跳動消失。
3. **海洋熱輸送**（`Climate.OceanHeatTransport`）：2° 一條的緯度帶做一維能量平衡，往輻射平衡溫度（34 − 60 sin²緯度）鬆弛、
   跟相鄰帶擴散熱量，擴散係數跟海洋比例成正比；陸地拿到大氣那一半的輸送，加上離海岸 800 km 指數遞減的海洋那一半。
   七成是海時赤道約 26°C、45° 約 8°C。45° 陸地暖了約 4～5°C。

**陸地太高**（回頭改 P4 的配置與劇本，2026-10-19 使用者決定）：
4. 起始大陸內陸厚度 38 → 35 km（起步時陸地平均高出海面 1.3 → 0.96 km）。
5. A 往西、C 往東北都放慢到 0.5 cm/yr。原本以為大陸面積縮小主要是被太平洋吃掉，放慢之後幾乎沒變——逐板塊量才發現
   是分散的：A 南（繞支點轉開讓西岸以 0.55 cm/yr 撞牆）、B（被 C 吃掉，B 撞 C 的縮短）、A 北與 C（撞牆）。
6. **太平洋隱沒到 A 南底下**（`ContinentScenario.IsUnconsumable` 改成看碰到的是哪塊板塊）：A 南不再被那道牆吃掉（40 Myr 少 22% → 約 1%）。
   試過讓 A 南往東滑來抵銷西推，A 北與 A 南之間的窄頸被拉開、斷成兩塊，撤掉。
7. **安地斯型造山**（`PlateFrameCrust.AndeanSubductingPlate`）：太平洋隱沒到 A 南底下時，大陸前緣被擠壓縮短，每隱沒一點就把
   35 km 的一半記進碰撞增厚（接觸的是大陸棚外側自己的海洋地殼時，造山量交給 150 km 內最近的大陸格）。不扣別處，質量不守恆，
   是劇本為了外觀做的調整。第一版用「隱沒洋殼的 50%」並套用在所有海洋隱沒到大陸底下的地方：A 南還是沒山，極區板塊反而在北岸堆出山。

**褶皺**（2026-10-19 使用者指出地球的造山帶是一整片被擠皺的地殼、不是只有一排山）：
8. 先把褶皺做進地殼厚度，結果被重力擴展（沒有侵蝕時唯一的增厚出口，等於擴散）在約 100 萬年內抹平。
   改成另一層**構造起伏**（`SimulationState.StructuralRelief`，跟著板塊座標系的地殼點走、不參與擴散，2,000 萬年的特徵時間衰減）：
   碰撞帶寬 300 km，厚度照舊平滑增厚，另外疊上 75 km 波長的起伏，每增厚 1 km 長 100 m（撞太平洋與安地斯型造山 400 m），上限 ±2,000 m。
   存檔格式升到 v7。
9. 褶皺谷地裡的小湖把破碎度推到 4.1 → **v2 的海岸破碎度只算碰到主洋的海岸**（`ContinentCriteria.InlandWaterIsCoast`）。

**結果**（n=150、種子 42 劇本，40 Myr）：冰蓋佔陸地 25%、表面 7.6%（地球約 10%／3%，冰期最盛約 25% 的陸地），鎖住 0.4% 的水；
海平面沒有週期跳動；停止條件成立（最大 48%、第二 44%、大島 2、破碎度 1.8／1.4）；B 撞 C、A 北西岸、A 南西岸都是帶褶皺的山脈。

**留給 P7 的問題**：陸地仍隨碰撞堆山慢慢變高變冷（40 Myr 時平均高出海面 1.8 km、45° 陸溫 −6.5°C，地球約 0.84 km），
陸地降水只有全球平均的 11%（地球約 75%，大陸邊緣的高地讓水氣在海岸就降光）。要靠侵蝕把山削低、把物質搬到海邊。

## P7 外營力

河流路由、侵蝕與沉積（掛在地殼柱上、每個累加量都有去路）、海浪按面海邊數計費。
**驗收**：河流從山流到海；沉積總量等於侵蝕總量；鋸齒海岸消失（若 P2 沒解決）。

### P7 結果（2026-10-19／20，分支 `feat/p7-erosion`，**驗收通過**）

全部只在板塊座標系模式生效（標記法的氣候、侵蝕 `Erosion`、停止條件都不變）。

**基準線**（種子 42 劇本、P6 結束時、40 Myr）：v1 的 `Erosion` 在 v2 裡也在跑，但剝蝕率只有 **0.7 公尺／百萬年**（地球約 50）；
沉積物掛在網格上，大陸移走之後在海上拖出條紋；41% 的沉積物堆在陸地的小窪地裡（最陡下降碰到窪地就停）；褶皺不會被侵蝕。

**陸地降水**（2026-10-19 使用者決定在 P7 一起修，侵蝕係數才不會拿來補降水的錯）：
1. P6 寫的「陸地降水 11%」是假象：海平面下降露出來的大陸棚還留著當海時的降水。**每次解完當下量，陸地只有全球平均的 0~1%**，
   陸地上空的水氣 0.03（海上 24）。
2. 原因是**地形抬升用水底的地表**：海上的空氣「從 −4 公里的海床爬上大陸坡」，靠岸的海格就把 56% 的水氣逼成雨。
   改成從水面算起（`Climate.OrographyAboveWater`）→ 陸地 21%。
3. 基礎降水「每次迭代 6%」等於「每格 6%」，跟解析度綁在一起（CLAUDE.md 第 4 條）：n=150 是每 15 公里 6%，水氣走 400 公里就降光。
   改成**每 200 公里 6%**（`Climate.BaselineRainReferenceKm`）→ 陸地 0.71（地球約 0.72），40 Myr 之間 0.84~0.96。
   陸地總降水量幾乎不變（由海岸進來多少水氣決定），改的是分布：海岸 1.7 倍、內陸 400 公里外約 0.1（中亞那種乾燥內陸）、20° 的副熱帶沙漠帶。

**沉積物跟著地殼走**（`PlateFrameCrust` 的每個地殼點帶 `_sediment`，存檔格式 v8）：
4. 隱沒時被吃掉那一點的沉積物**刮進增積楔**——換成地殼厚度併到留下的那一點（2026-10-19 使用者選定），沉積物有去路、不會在海溝那一格無上限累積。
5. 寫回時混疊出來的點**照抄沉積物、不加差值**：加差值的話同一格的堆積每一步多拿一份，之後顯示出來是兩倍厚的沉積柱（單格 39 公里、四周 18 公里）。

**v2 的外營力**（`FluvialErosion`，取代 v1 的 `Erosion`）：
6. 流向用 P5 的泛洪（越過淺窪地、只有存水的湖留得住泥沙），流量用 `Hydrology.Discharge`，坡度以下游的**水面**為基準。
7. 刨蝕順序：沉積物（換算均衡反彈，拿掉 1 公尺地表只降 0.24 公尺）→ 凸起的褶皺（1:1）→ 基岩（大陸 0.18）。
8. 進湖的泥沙依水深比例鋪在湖底、最多填到湖面，多的從溢出口往下游。進海的從河口一圈一圈往外（陸地也走過去、只填海格），
   先墊到海面下 130 公尺（大陸棚），2,000 公里內都墊滿了才墊到接近海面——沉積物不會自己長出海面。
9. **基準面**：什麼營力都刨不到海平面以下；**浪基面**：海浪只算外面是 200 公尺以上深水的邊（寬的大陸棚把浪的能量消耗掉）。
10. 一步最多降 200 公尺（4 公釐／年，地球最快的造山帶）、河流一步最多刨掉往下游落差的一半。
11. 係數 K = 6,000（2026-10-20 使用者選定，對著陸地高度校準）。

過程中排除的問題（每一條都是畫圖或印個體才看到的，統計量看起來都正常）：
- 進海的泥沙「往最深的海鄰居一格一格走、走不下去就倒在那裡」：最高的 300 格陸地平均 5.9 公里沉積物。
- 窄海裡 600 公里內只有幾格，裝不下的平均倒在那幾格、墊出海面。
- **上一步的主洋種子沒有流向**：海平面降了之後露出水面，整條河的泥沙每一步倒在那一格（12~23 公里／步），堆出 20~30 公里的沉積柱。
- 水深是上一步的，板塊動過之後河口接到一兩格孤立的小水窪，只走海格的話整包倒在那一格。
- 海浪與風化沒有基準面：低平原被一路刨到海面下、海岸一直後退，40 Myr 時兩塊大陸北部整片變淺海、一座大島沉掉。

**結果**（n=150、種子 42 劇本，40 Myr）：

| | P6 | P7 | 地球 |
|---|---|---|---|
| 陸地平均高出海面 | 1.8 km | **0.93 km** | 0.84 km |
| 最高峰 | 10.1 km | **8.9 km** | 8.8 km |
| 陸地佔表面 | 30% | 31.6% | 29% |
| 剝蝕率（物質厚度） | 0.7 m/Myr | 194 m/Myr | 約 50 |
| 陸地降水／全球（解完當下） | 0.01 | 0.95 | 約 0.72 |
| 冰蓋佔陸地 | 25% | 17% | 約 10%（冰期最盛 25%） |
| 停止條件 | 成立 | **成立**（48%／45%、大島 2、破碎度 2.9／2.9） | |

侵蝕總量等於沉積總量（每一步都相等），備援路徑（就地堆、平均鋪）累計 0。係數比較：K = 3,000 陸地 1.10 公里；
K = 10,000 最高峰 10.4 公里、第二大陸破碎度 4.3 超過上限。

**停止條件的大島下限 1% → 0.8%**（只在板塊座標系，2026-10-20 使用者決定）：侵蝕把劇本的第二座大島削到陸地的 0.84~0.89%。

**使用者接受的現象**：兩塊大陸北方的低平原（P6 時的湖區）在出口被刨到海平面之後變成內陸淺海，類似哈德遜灣、波羅的海。

**留給之後的問題**：剝蝕率約地球的 4 倍（為了把碰撞堆的山削下來）；大陸棚很寬；陸地降水比地球略多；
河流和湖還沒接到前端（2026-10-19 使用者決定 P7 只做後端，留到 P9）。

## P8 校準

全部在 n=150 上一次校準，目標：停止條件觸發時海洋 60%~72%、高度分布雙峰、
洋脊在海平面下 2,000~3,000 m、主洋佔水域 > 95%、冰帽 < 10%。
不能用靜態反算（v1 量到水量會改變演化方向），只能夾逼實測。

### P8 結果（2026-10-20，分支 `feat/p8-calibration`，**驗收通過**）

全部只在板塊座標系模式生效。量測點是種子 42 劇本**停止條件第一次觸發**的那一刻（劇本 40 Myr 結束後才開始檢查，觸發在 41.0 Myr）。
儀表在探針 `CalibProbe`（海洋、主洋、冰、停止條件、陸地高度分布、大陸棚、洋脊、淨輸出到海）與 `UpliftProbe`（抬升來源對帳）。

**基準線**（P7 結束時）：規劃的目標除了冰幾乎都已達標——海洋 68.7%、高度分布雙峰、洋脊中位 −2,203 m、主洋 99.8%、
冰佔表面 5.1%、**佔陸地 15.7%**（2026-10-20 使用者指定「冰帽 < 10%」指的是佔陸地）。另外三項使用者要一起校準：
陸地高度分布（34% 的陸地擠在 1~1.5 km 的高原）、剝蝕率（約 190 m/Myr，地球約 50）、大陸棚寬度。

**量出來的事**：
1. **大陸棚其實不寬**：主洋 ≤ 200 m 只佔表面 5.0%（地球約 7.5%）。P7 看圖說「偏寬」是誤判，淺藍色大多是北方的內陸淺海與湖。不調（使用者決定）。
2. **剝蝕率高不是在抵銷造山**：各種增厚來源加起來都小於侵蝕刨掉的基岩（40 Myr 間每百萬年約 200 萬 km³），
   大陸地殼總體積 40 Myr 少了 9%——侵蝕主要在把起始那片太高的高原削下來。安地斯型造山（不守恆的那一份）約佔增厚的 13%，不是主因。
3. **低地是侵蝕削出來的**：K 調低剝蝕率會降，但低地變少、陸地變高變冷（K = 1,000：剝蝕 83、0~0.5 km 只剩 16%、冰 19.9%）。
   剝蝕率與高度分布互相衝突，使用者選「以高度分布為主」：K 維持 6,000，剝蝕率改用「淨輸出到海」記錄（約 166 m/Myr），不追 50。
4. `SimulationEngine` 的 `oceanDepthMeters` 在大陸配置模式是**死的**（水量由 `ContinentLayoutParameters.InitialSeaLevelMeters` 決定）。

**調整**：
5. **起始大陸地殼**（2026-10-20 使用者選定，大陸形狀與板塊不變）：海岸 32 → 31 km、內陸 35 → 34 km、
   加厚距離 400 → 1,200 km、厚度雜訊 ±2.5 → ±4 km。壓低整片只會讓平台整片下移（內陸 33：54% 擠在 0.5~1 km），
   加厚得慢、起伏大，0~0.5 km 才到 48%。
6. **全球溫度偏移 +4°C**（`Climate.GlobalTemperatureOffsetC`，使用者選定加溫而不改積冰門檻）：有冰的陸地年均溫中位 −5.9°C，
   +1/+2/+3°C 只壓到 11.8/11.4/10.2%；+4/+5/+6 是 9.4/8.8/8.0%，選 +4 是因為第二大陸的海岸破碎度離上限最遠（3.2，+5 是 3.7）。

**結果**（n=150、種子 42 劇本、41.0 Myr 停止條件觸發）：

| | 目標 | P7 結束 | P8 | 地球 |
|---|---|---|---|---|
| 海洋 | 60~72% | 68.7% | **68.9%** | 71% |
| 高度分布 | 雙峰 | 雙峰 | **雙峰**（海床 −4.5~−5 km、陸地 0~0.5 km） | 雙峰 |
| 洋脊 | −2,000~−3,000 m | −2,203 | **−2,182**（P10 −2,313、P90 −1,958） | 約 −2,500 |
