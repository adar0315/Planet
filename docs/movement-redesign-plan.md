# 走動方式改版規劃：從跳格改成連續移動

## 目標

- **滑順轉向**：面向不再只有 0/60/120/… 六個值，而是連續角度
- **前進、後退**
- **左右橫移**
- **翻滾／閃避**：短距離、快速、有冷卻的位移

---

## 現況（2026-10-16 盤點）

| 項目 | 現在的做法 | 檔案 |
|---|---|---|
| 位置 | 玩家「在某一格」，`gameState.currentTile` | `playerMovement.ts` |
| 移動 | 按鍵 → 跳到相鄰格，立即生效、背景向伺服器驗證 | `playerMovement.ts` |
| 面向 | `facingDeg` 只有 6 個值，轉向有動畫但目標是 60° 的倍數 | `gameState.ts`、`cameraRig.ts` |
| 方向鍵 | 6 個插槽（`upLeft`/`right`…）依面向指派給鄰居 | `bearing.ts` |
| 輸入 | 只處理 `keydown`，每次按鍵一個動作，有冷卻 | `inputHandlers.ts` |
| 伺服器 | `MovementHub.MoveTo(from, to)` 驗證「to 是不是 from 的鄰居」 | `MovementHub.cs` |
| 時間 | 步進模式下每走一格 `advanceTime(1)` | `playerMovement.ts` |
| 角色 | **沒有角色模型**，鏡頭就是玩家 | — |
| 尺度 | 細網格一格邊長約 1 公里 | — |

**這套架構的核心假設是「玩家永遠站在某一格的中心」**。連續移動推翻的就是這個假設。

## 已拍板（2026-10-16）

| 決策 | 選擇 |
|---|---|
| 1. 移動模型 | **連續位置**，所在格由位置推導 |
| 2. 速度尺度 | 採建議值（走 200 m/s、跑 600 m/s、翻滾 0.35 秒 400 m），實作後再調手感 |
| 3. 地形規則 | **上坡限 2 級、下坡不限；淺水涉水減速、深水擋住；撞牆沿牆滑開** |
| 4. 轉向輸入 | **鍵盤＋滑鼠並存**（按住轉向鍵固定角速度；按住右鍵拖曳轉向） |
| 5. 角色模型 | **先放簡單幾何體**，翻滾時做翻轉動畫 |

以下是當時的選項分析，保留作為決策依據。

## 需要先拍板的決策

### 決策 1：連續位置 vs 動畫化的跳格

| | A. 連續位置（建議） | B. 仍然跳格，只是動畫滑順 |
|---|---|---|
| 位置 | 球面上任意一點，「目前所在格」由位置推導 | 仍在格子中心 |
| 橫移、翻滾 | 自然支援 | 只能「滑到旁邊那格」，翻滾＝跳一格 |
| 轉向 | 任意角度 | 任意角度可以，但前進方向仍得落在 6 個鄰居之一 |
| 改動量 | 大 | 小 |

你描述的「滑順轉向＋橫移＋翻滾閃避」是動作遊戲的手感，**B 做不出來**——
面向 37° 時按前進，B 只能走向最接近的鄰居方向（30° 或 90°），會一直被「吸」向格子方向。

### 決策 2：移動速度的尺度

一格約 1 公里。真實步行 1.4 m/s，走過一格要 12 分鐘——在 2,002 萬格的星球上等於不能玩。
需要一個「遊戲速度」，例如：

| 動作 | 建議值 | 走過一格 |
|---|---|---|
| 走 | 200 m/s | 5 秒 |
| 跑（按住 Shift） | 600 m/s | 1.7 秒 |
| 翻滾 | 0.35 秒內位移 400 m | — |

這等於把「角色」的尺度定在遠大於人的程度，跟現在鏡頭的高度與 8 倍高度誇張是一致的。

### 決策 3：地形能不能走

格子是平頂、格與格之間有高度落差（誇張 8 倍後 40~160 m）。要決定：

- **爬坡上限**：相鄰格高度差超過幾級就是牆、走不上去？（建議 2 級，相當於現在落差的 p90）
- **水**：能不能走進水裡？（建議：淺水可以涉水但減速，深水擋住——之後要游泳/船再說）
- **下坡**：可以直接跳下去，還是一樣受上限限制？（建議：下去不限）

### 決策 4：轉向用什麼

- **鍵盤**：按住左右轉鍵，以固定角速度轉（建議 120°/秒）
- **滑鼠**：按住右鍵拖曳轉向（現在拖曳是轉鏡頭）
- 兩者並存

### 決策 5：要不要角色模型

翻滾需要一個看得見的身體才有感覺。最小版本可以是一個簡單的幾何體（膠囊／錐形指向面向），
翻滾時做一個翻轉動畫；之後再換真的模型。**沒有身體的話，翻滾只是鏡頭突然往旁邊平移，很難辨認。**

## 建議設計（以 A 為前提）

### 狀態

```ts
playerPosition: Vector3     // 單位球面上的點（世界座標除以半徑）
headingDeg: number          // 連續角度，0=北、順時針
velocity: { forward, right } // 本地切平面上的速度（公尺/秒），有加減速才滑順
dodge: { active, startedAt, direction, cooldownUntil }
currentTile: TileDto        // 由位置推導，不再是主狀態
```

### 每一幀

1. 讀按住中的鍵（**需要 `keyup`**，現在只有 `keydown`）→ 目標速度
2. 轉向：`headingDeg += turnInput × 角速度 × dt`
3. 速度往目標值靠近（加速度上限，起步與停下才不會生硬）
4. 翻滾中則以翻滾位移取代一般速度
5. 在切平面上位移，再投影回球面（球面上「直走」就是沿大圓）
6. **推導目前所在格**：只需檢查目前格與它的 6 個鄰居誰最近（Goldberg 格是 Voronoi，最近的格心就是所在格），每幀 7 次內積
7. 跨格時檢查地形規則（決策 3）；不能進就沿牆滑動，而不是硬停
8. 地面高度：站在所在格的頂面；跨格的瞬間高度用短動畫過渡，不要瞬移
9. 鏡頭跟在角色後上方，面向平滑跟隨

### 伺服器

**現有的 `MoveTo(from, to)` 驗證可以保留**：連續移動仍然是一次跨一格，
跨格時送一次驗證就好。唯一要注意的是翻滾的距離必須小於一格，否則一幀可能跨兩格。

多人時才需要加速度／距離合理性檢查，現在不用。

### 步進模式的時間

從「每走一格推進 1 小時」改成「每跨一格推進 1 小時」——語意不變，只是觸發點改成跨格事件。

## 分階段

| 階段 | 內容 | 驗收 |
|---|---|---|
| **M1** | 連續面向＋前進後退，所在格由位置推導；暫時無地形規則、無角色 | 面向任意角度按前進，走的是直線不是鋸齒；跨格時伺服器驗證全部通過 |
| **M2** | 左右橫移、加減速、跑 | 斜向移動（前＋右）速度正確，不是 √2 倍 |
| **M3** | 地形規則：爬坡上限、水、沿牆滑動、跨格高度過渡 | 走向懸崖會沿著牆滑開而不是卡住 |

## 風險

- **極點附近**：「北」在極點沒有定義，現在的切平面基底在極點會退化。連續移動會真的走到極點，要換一個不依賴北的基底（用前一幀的面向平移過去）
- **五角格**：只有 5 個鄰居，推導所在格時要用實際鄰居清單而不是固定 6 個
- **patch 邊緣**：連續移動比跳格更快到達邊緣，預載入的距離門檻要重估
- **浮點精度**：半徑 185 萬公尺，float32 在這個尺度上精度約 0.1 m。位置要用單位向量或 float64 保存，不要用世界座標的 float32
