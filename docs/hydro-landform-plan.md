# 水文與地貌規劃：江河、侵蝕堆積、岩性、風與海浪、四季、近看細分

## Context

使用者反映：星球上缺少水量充沛的江河，也看不到侵蝕和堆積造成的地形，例如深切的河谷、沖積平原、河口三角洲。使用者希望：
- 河水除了降水，還要有地下水基流、高山冰雪融水、湖泊濕地調節。
- 岩石有軟硬之分，軟硬不同就侵蝕得不一樣。
- 除了流水，還要有風蝕和海浪侵蝕。
- 要有四季變化。
- 近看時，地塊再切成更小的六角形，取代用畫的河道紋路。

兩個探索代理盤點出來的現況：

| 層 | 現況 |
|---|---|
| 模擬（n=150，每格約 15 km，每步 5 萬年） | 河水只來自降水（`Hydrology.cs`：降雨逕流 0.35，降雪 0.8）。<br>沒有地下水，沒有季節（氣候是全年平均的穩態，每 200 萬年解一次），沒有冰川融水；湖泊只算水量平衡、沒有調節作用。<br>侵蝕的 K 是全球同一個值，沒有岩性（`CrustType` 只分洋殼和陸殼）。<br>搬運沒有容量上限，所以陸地上不會堆積；海裡的堆積最高只到海平面下 5 m。結果是沒有沖積平原，也沒有三角洲。<br>沒有風蝕；海浪只有「每個深海鄰居 30 m/Myr」這一項。 |
| 放大（1 km 地塊，約 2,000 萬格） | 只有高度做了內插，其餘全部照抄最近的粗格。<br>河流是從粗格中心到下游格中心的直線，有 60° 折角，沿線整格塗成淡水。<br>河道沒有刻進地形。`Mud`、`Loess`、`Cliff`、`Gravel` 這些地形類型從來沒用到。 |
| 前端 | 星球已經有 23.44° 的地軸傾角（`frontend/src/map/sunPosition.ts`），太陽會南北擺動，但地表不會隨季節改變。 |
| 已知錯誤 | 陸地的冰厚算了兩次（`PlanetMaterializer.cs:74`）。<br>高地的湖被強制壓到 −5 m，變成坑（`SimulatedTerrainSampler.cs:60`）。 |

### 使用者的決定（2026-10-23～24）

| 項目 | 決定 |
|---|---|
| 近看 | 地塊再細分成小六角形，倍率 ×4（每邊約 250 m、每格約 16 個），只在玩家附近即時產生、不存資料庫。拉遠時，有河的地塊整格顯示成河水的藍色 |
| 水源 | 地下水基流、冰雪融水、湖泊調節都要做，搭配四季 |
| 四季 | 氣候分 12 個月，月與月之間平滑過渡。影響**河湖水位**、**積雪與結冰**、**氣溫與降水的顯示**（植被顏色這次不做） |
| 四季與地質演化 | 演化仍用全年平均，另外用一個「洪峰係數」加強侵蝕與搬運；每次重解氣候時一起更新 |
| 岩性 | 由地質歷史算出來，跟著板塊座標系的地殼點一起移動 |
| 風與海浪 | 風蝕加黃土、沙丘、海崖與沙灘，四項都做 |

## 原則（沿用 CLAUDE.md）

- **分工**：模擬算「哪裡、多少」；放大和近看細分負責「長什麼樣子」。兩者共用同一個**地貌取樣器**（`LandformSampler`，輸入球面上任一點，回傳地形、高度、水面高度、河道距離）。地塊取樣在格心，小六角取樣在小格心，所以兩邊一定一致。
- 岩性、黃土是地殼柱的一部分，要掛在 `PlateFrameCrust` 的地殼點上，並且要進存檔。續跑測試 `Snapshot_ContinentScenario_ResumeIsBitIdentical` 守門；洪峰係數這類跨步驟的狀態也一樣要進存檔。
- 每個會累加的量都要有去路。
- 參數寫成物理量，不寫格數。
- 每一階段都要畫圖驗收，不能只看統計。改配置時，先畫第 0 步的圖給使用者確認。
- 只有 v2 打開新機制，v1 的行為不變。
- 鄰居座標只准由後端推導：小六角的鄰居也由後端算好再送給前端。

開工時把這份規劃寫進 `docs/hydro-landform-plan.md`，各階段的結果也記在那裡。

## 分階段

### H0　放大的兩個錯誤（小）
- `PlanetMaterializer.cs:74`：陸地不要再加一次冰厚。
- 湖面高度（`Hydrology.LakeLevelAt`）寫進 `PlanetCell`，新增欄位 `WaterSurfaceMeters`。湖的地塊 `SeaLevel` 填湖面高度、`ElevationLevel` 填湖底，不再強制設成 −1。前端本來就是用 `elevationLevel < seaLevel` 判斷水下。

### H1　岩性（模擬）
- 新增 `Lithology`，掛在板塊座標系的地殼點上：

| 岩性 | 侵蝕係數 | 透水性 | 來源 |
|---|---|---|---|
| 結晶基盤 | 0.5 | 低 | 起始大陸的內陸核心；碰撞時抬出地表 |
| 火山岩 | 0.8 | 中 | 裂縫噴發、地函柱、隱沒帶火山弧 |
| 沉積岩 | 1.6 | 高 | 被埋夠深的沉積物，隨時間成岩 |
| 混雜岩 | 1.2 | 中 | 隱沒時刮進的增積楔 |
| 洋殼玄武岩 | 0.8 | 低 | 洋殼 |

- 鬆散沉積物沿用 `SedimentThickness`，侵蝕係數 2.0。
- 起始大陸：內陸是結晶基盤，海岸往內約 300 km 是沉積蓋層。
- 存檔格式升到 v10。演化視角新增「岩性」圖層。**先畫第 0 步和 41 Myr 的岩性圖給使用者確認。**

### H2　流水侵蝕與堆積（模擬）
修改 `FluvialErosion.cs`：
- 侵蝕係數乘上岩性係數，再乘上**洪峰係數**（H3 算出）。
- 加入搬運容量 `Qs_cap = Kt · Q^m · S`，載量超過容量就在陸地上堆積，形成沖積扇和沖積平原。
- 河口允許沉積堆到海平面以上幾公尺，讓三角洲長出陸地；三角洲的成長同時被海浪削減（H5）。
- 每格存下給放大用的診斷量，並寫進 `PlanetCell`：下切速率、堆積速率、河口堆積通量、冰蝕累積。
- 守門：侵蝕量等於堆積量、續跑位元相同、沉積物不會堆成柱子（P7 踩過的坑）。

### H3　12 個月的氣候（模擬）
修改 `Climate.cs`：
- 新增 `SolveMonthly`。每個月依太陽赤緯算日照（傾角 23.44°，跟前端 `sunPosition.ts` 同一個公式，要抽成共用常數並交叉檢查）。
- 海洋有熱慣性：月溫的振幅變小、時間延遲約 1～2 個月。陸地反應快。
- 風帶和雨帶跟著太陽南北移動，做出季風、乾濕季。
- 降雨還是降雪依月溫決定。
- 每次重解氣候（每 200 萬年）也解這 12 個月，算出每格的**洪峰係數** = (最大月逕流 ÷ 平均月逕流) 的函數，交給 H2。洪峰係數要進存檔。
- 演化本身仍用全年平均的穩態，速度大致不變；每次重解氣候的成本約變成 12 倍，要實測。
- `PlanetCell` 新增每月的氣溫與降水，以 12 個 float 的二進位欄位存放。

### H4　四季的水文：地下水、冰雪、湖泊（模擬）
修改 `Hydrology.cs`，新增「年循環」計算，每次重解氣候時跑一次：
- **土壤與地下水**：線性水庫，滯留時間由岩性透水性加沉積物厚度決定。雨季入滲，乾季以基流慢慢釋放。
- **積雪**：月溫低於 0°C 時累積，用度日法在春夏融化。
- **冰川**：夏季融水，用 `IceThickness` 的面積計算；冰的質量平衡要同時檢查。
- **湖泊**：蓄水使出流變得平滑，湖面跟著季節漲落。
- **沿途損失**：乾燥地區的河道會蒸發和滲漏，雪山的水流進沙漠時可能消失在半路，或流進內陸湖。
- 反覆跑年循環，直到結果每年都一樣（要設次數上限，超過就丟例外，見 CLAUDE.md 3.7）。
- 輸出每格 12 個月的流量、積雪、湖面高度、是否結冰（河湖、海冰）。依每月流量把河分成**常流河／季節河／間歇河**，並找出洪峰月。
- 河的門檻從 1 萬 km² 降到約 1,000 km²，因為近看細分後小河也看得到。
- `PlanetCell` 新增：每月流量、每月積雪與結冰、`FlowRegime`、平均河寬。要一個資料庫遷移。

### H5　風與海浪（模擬）
- **風蝕**：乾燥又沒植被的地區，吹蝕鬆散沉積物。細顆粒順著風向搬到比較濕的地方，成為**黃土**（新增厚度欄位，掛在地殼點上，可以被流水再侵蝕）；粗顆粒留在原地成為**沙海**。
- **海浪**：浪蝕乘上岩性係數。依「開闊海面的風浪距離 × 岩性」決定海岸類型：硬岩是海崖，軟岩或沉積物供應多的地方是沙灘或礫灘。
- 守門：質量守恆，而且每個量都有去路。

### H6　地貌取樣器與放大（後端）
- 新增 `LandformSampler`，輸入球面上任一點，回傳地形、高度、水面高度、到河道中心的距離、是不是泛濫平原、河道屬於哪個粗格（用來查每月流量）。內容：
  - **河道路徑**：通過粗格中心的平滑曲線，加上用固定種子產生的曲流；平原上蜿蜒，山區比較直。取代現在 60° 的直線折角。
  - **河谷斷面**：硬岩和陡坡是 V 形，冰蝕過的是 U 形，堆積河段是寬而平的泛濫平原。深度和寬度由 H2 的診斷量決定。
  - **三角洲**（有分流河道）、**沖積扇**、**海崖**、**沙灘與礫灘**、**黃土**、**沙丘**（走向由風向決定）、**硬岩露頭**（`Rock`）。
- 取樣器在服務啟動時從 `PlanetCells` 建好（22.5 萬格加河網，常駐記憶體），所以放大和近看細分用的是同一份資料。
- 放大時，每個地塊在格心取樣。地塊新增兩個欄位：`RiverWidthMeters`（這格範圍內最大的平均河寬，0 表示沒有河）、`RiverCellId`（查每月流量用）。拉遠時靠這兩個欄位把整格塗成藍色。要一個遷移。
- 效能預算：放大總時間不超過現在的 1.5 倍（現在 527 秒）。取樣器要有空間索引。
- 用 `MaterializeProbe` 畫三個區域的 1 km 圖給使用者看：大河河口、山區峽谷、沙漠和它的下風處。

### H7　近看細分成小六角形（後端＋前端）
**後端**
- 用同一套 Goldberg 網格，頻率 1415 × 4 = 5,660，只即時產生、不存資料庫。
- 新增端點 `GET /api/tiles/subtiles?tileIds=…`，回傳這些大格底下所有的小六角：
  - 每個小六角歸屬離它最近的大格。候選只要看對應位置的大格和它的鄰居。
  - 地形、高度、水面高度用 `LandformSampler` 在小格心取樣，另外帶上到河道中心的距離和是否為泛濫平原。
  - 鄰居 id 由後端的鄰居推導算好一起回傳，前端只查表。開工前要先確認 `TileNeighborResolver` 能用任意頻率。
- 小六角的 id 由（面、列、欄）編碼成 long，不跟地塊的 id 衝突。

**前端**
- 新增 `scene/subTileManager.ts`。鏡頭距離低於門檻（約 8 km，實作時調）時，向後端要玩家附近（半徑約 15～30 km，約 5,000～20,000 個小格）的小六角，合成一個 mesh。用的是 `buildTilePatchMeshSliced` 同一套。
- 被小六角取代的大格要藏起來：`tilePatchMesh` 新增依格子隱藏的功能。細分區最外圈因為邊界是鋸齒狀，會有約半個小格寬的接縫；那裡離鏡頭最遠，可以接受。
- 角色移動、跨格偵測、伺服器驗證仍然用大格，不受影響。

### H8　四季顯示（前端）
- `gameState.gameTime` 換算成一年中的位置，在相鄰兩個月之間內插。南北半球的差別，資料裡已經有了（每格各自的月值）。
- **河湖水位**：
  - 近看：小六角依「到河道中心的距離 < 當月河寬的一半」決定是不是水。當月河寬由平均河寬和當月流量比換算。洪峰時泛濫平原淹水，間歇河乾季時露出礫石河床。
  - 拉遠：有河的大格，有水時是藍色，乾涸時是河床色。
- **積雪與結冰**：依當月積雪把格子改成雪色；河湖結冰改成冰色；海冰擴張和退縮。做法沿用 `recolorAll`，跟現有的日夜時段換色一起算。
- **HUD**：當地的季節名稱（依半球）、當月氣溫、降水。
- 每月資料的來源：`nearby` 的回應附上這批地塊用到的粗格月值，以 `SourceCellId` 去重，不必塞進 2,000 萬列的地塊表。

### H9　校準與正式部署
- 重跑 v2 劇本到停止條件，用 `CalibProbe` 比對之前的數字：海洋比例、高度分布、淨輸出到海。目標：
  - 平原和三角洲有出現。
  - 濕潤區以常流河為主。
  - 季風區有明顯的洪峰。
  - 外來河看得到。
- 部署順序：先套遷移，再 publish（需要使用者停止、啟動服務），再 build 前端。
- 最後由使用者在正式站跑模擬並按「放大」。這一步會覆蓋 2,000 萬地塊，我不代按。

踩到的坑：
- **搬運容量第一版太小**：3×10⁵ 時陸地有 83% 以堆積為主、36% 露出鬆散沉積物。提高到 3×10⁶。
- **三角洲第一版沿整條海岸線長**：每一格靠海的陸地都「流進海」。改成只有真的河（集水 1 萬 km²）才長。
- **風蝕第一版堆出 21 公里高的塵土柱**：風停的地方（副熱帶高壓）找不到落點，整條路的塵土全倒在那一格，那一格又沒有風可以吹走。改成乾燥的地方沿路慢慢落、風停時沒落下的放回原地，只有被植被攔下的才算黃土。
- **續跑分歧（蓋層岩性）**：新生洋殼重設了蓋層厚度卻沒重設種類，沒存檔的舊值讓讀檔續跑在第 2 步分歧。
